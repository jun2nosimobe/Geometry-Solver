§05 b45。三角形 ABC と辺(の直線)BC・CA・AB の上の点 D・E・F の向きつきの比の積 (AF/FB)(BD/DC)(CE/EA) は、D・E・F が共線なら −1(メネラウス)、AD・BE・CF が1点で交わるなら 1(チェバ)。どの比も同じ直線の上の差の比なので、形式的な対数では線形な等式になる。
等式: 3辺が図にある三角形と、図にある横断線・1点で交わる3本の直線について等式を入れる(固定座標で積が −1・1 であることも確かめる)。
検出(逆): 2辺の上の点を通る直線 t があり、3つ目の辺の上の点で積の式が −1 に還元されれば、その点を t に接続する(メネラウスの逆)。2本の直線が O で交わり、3本目の候補で積が 1 に還元されれば接続する(チェバの逆)。固定座標で「その点がその直線に乗る」が真の候補だけを格子で確かめる。三角形の枠(点・2点を通る直線・三角形・直線ごとの点)は相似と共有し、1回の追跡で1度だけ作る。
監査で見つけて直したこと: AR の前提を「memo から引いた実体の番号」で記録していて、その実体がその時点では別の同値類にいることがあった(時刻つきの監査で「自分の結論を前提にした」時刻の逆転に見えた ― nine_point_full)。「この定義がこの同値類にある」(DefinedBy)として記録するようにした。既に接続している組には、理由つきの接続でも理由を記録しない。

#85等方線束で長さを比のまま AR に入れ、相似(AA)と相似で対応する点を AR で出す ― 方冪・交わる弦の相似の2定理を置き換え、2015 APMO・2018 CHN Western・centroid が解けた既定
§05 b45。ユーザー案: 相似の定理は複比だけで書けるが大きすぎたので AR で表したい、比ではなく複比を使う、長さの足し算は符号が難しいので扱わず全て比で表す。
表現: 虚円点 J・I からの線束の要素 JX, IX を記号にする。直線 m の上の X, Y で s(JX,JY) − s(X,Y) = κ_J(m)、κ_J(m) − κ_I(m) = β(m の方向) + 定数(直線の上の比と方向の角をつなぐ地図の等式)。|XY|² = (z_X − z_Y)(z̄_X − z̄_Y) なので LengthSq(X,Y) = s(JX,JY) + s(IX,IY)、積は和。
相似(検出と結論): 3辺が図にある三角形の2つの角の正準な剰余を鍵に、同じ鍵なら同じ向きの相似、符号を変えた鍵と一致すれば裏返しの相似。同じ向きの相似は I と J を動かさないので、対応する辺ごとに s(JX′,JY′) = s(JX,JY) + log a と I の線束の同じ式(裏返しは I と J を入れ替える)。仮定の角から結論を出す部分だけは線形でないので検出で出す。
相似で対応する点: 辺 XY の上の点 P と対応する辺の上の点 P′ について、σ(X) = X′ からの2つの等式が格子で言えるなら P′ = σ(P)。同じ直線の上ではこれは内分比 XP/XY = X′P′/X′Y′ が言えることと同じで、中点に限らない。分かった対応点は頂点・他の対応点との組で σ の等式を足す。2011 バルカン(中線どうしの対応)が交わる弦の相似の定理なしで解ける。
2つの定理を外した: AR が有効なら、共点二弦の相似(方冪の定理の基礎)と交わる弦の相似を既定で外す(--chord-theorems で残す)。
差分で積む形(ユーザー案)を試してやめた: 格子を呼び出しをまたいで持ち越し、マージされた実体の古い記号を「古い代表元の記号 = 新しい代表元の記号」でつなぐと、(1) 古い記号の行が溜まって行が3倍(971 → 2918)になり、どの段も毎回作り直すより遅い(等式を入れる段 0.14秒 → 1.09秒、egmop1 ノイズ10 の壁時計 4.4秒 → 8.2秒)、(2) 行の出どころが行どうしの組み合わせのたびに合併されて太り、1回の併合の前提が平均 227 → 6374 個、取り出した証明が 3.7万 → 103万ステップになってメモリが尽きた。e-graph は union-find で代表元にまとめ、マージの理由も1件ずつ持つので、この2つは定理の側では起きない。
速くしたのは簡約の使い回し: 角は2方向だけで決まるので方向・方向の組ごとに1度だけ簡約し、検出は記号1つずつの剰余の和を簡約し直す。使い回した剰余は出どころが太るので、併合に使う式だけ直接簡約して出どころを取り直す。egmop1 ノイズ5 で相似の検出 9.0秒 → 0.3秒、平行・共円の検出 4.9秒 → 1.1秒。nine_point_full は相似を入れた直後の 1.04M・14秒 → 57万・4.4秒。

#84AR に比と平行を入れる ― 同じ直線の上の無限遠点までの差を一定にして複比を本物の比にし、平行 ⇒ 比と、その逆(比 ⇒ 平行、中点連結定理の一般化)を出す既定
§05 b45。ユーザー案: 中点連結定理は比が一定であることから傾きの一致を帰結するので複比だけで書ける、一般の比の一致から平行を導く方に広げ、逆も入れる。
アフィンの等式: z = 1 の座標では、同じ直線 L の上で [X ∞_L R] が X によらないので s(X,∞_L) が一定。これで無限遠点との複比が本物の比になる(中点 (A,B;M,∞) = −1 から AM = MB)。
中点の比: 無限遠点との複比 −1 は AM = MB しか言わず、BA = 2·BM は足し算からしか出ないので、中点の定義から s(A,B) = s(A,M) + log 2 を入れる(log 2 は新しい記号)。
平行 ⇒ 比: 平行線の族に沿った2直線の間の射影はアフィンなので、対応する2点の差の比が一定(s_{L2}(X2,Y2) − s_{L1}(X1,Y1) = κ)。2直線の交点は自分自身に対応する。
比 ⇒ 平行(検出): 2直線を切る2本の横断線について、交点からの比(2直線が交わる場合)、または既に平行な横断線を基準にした比が一致すれば平行として方向を併合する。
結果(aff1、基準 gen1 との比較): 全設定で解けた問題は同じ、幾何平均 +0.8〜+1.4%、20%超の悪化なし。検査なしの監査で偽のマージ0件。単独では解ける問題を増やさないが、#85 の相似で対応する点(内分比が等しい点)がこの比の等式に乗っている。中点連結定理の定理はまだ外していない。

§05 b45。ユーザー案: すぐ AR にできるものを AR にし、まだできないものを考える。

#82代数的な追跡(AR)― 有向角・点の複比・線束の複比を形式的な対数の線形代数(ℤⁿ ⊕ ℤ/4)でまとめて閉じる。pappus と test_involution(ノイズ20)が解けた既定
§05 b45。ユーザー案: 複比の型をまとめて扱う、数値の対数は取らず形式的に(積を和のように)扱う、ℤ 上で考え虚円点の ±i のためにねじれを ℤ/4 にする。
表現: 同じ直線の上の2点の差を記号 s(X,Y)(s(Y,X) = −s(X,Y)、入れ替えはねじれ 2)として、評価器の複比 (A,B;C,D) = s(A,C)·s(D,B) / (s(C,B)·s(A,D))。有向角は虚円点との複比 (I,J;D1,D2)、線束の複比は方向の点の複比なので、どれも無限遠直線を含む直線の上の点の複比として同じ形。比は無限遠点との複比として入れる: 中点 (A,B;M,∞) = −1、調和共役 (A,B;C,D) = −1(方向の点が図に無い直線は、直線ごとの仮の無限遠点)。
計算: 同値類の中の2つの式の差を等式として整数の格子に積み(エルミート標準形の逐次挿入、主成分が割り切れないときは拡張ユークリッド)、各同値類の式を正準な剰余に還元して、剰余が同じ同値類を併合する。(I,J;D1,D2) の式が 0 に還元される方向どうしも併合する(平行)。ℤ の上なので 2θ₁ = 2θ₂ から θ₁ = θ₂ は出ない(有向角 mod π で健全)。証明の前提には、差を消すのに使った等式を記録する。手が止まったとき、回復の手(補助作図など)と同じ回に1回回す(logic_core/ar.rs、--no-ar で外せる)。
安全策: 各定義を記号の式に写したら、固定座標で式の値(基準点 R の行列式 [XYR] の積)と定義の値が一致することを確かめ、一致したものだけを使う。これが評価器のコメントの誤りを捕まえた: calc_cross_ratio はコメントの τ_D/τ_C ではなく τ_C/τ_D を返していて、最初は全ての定義が確認で外れた(コメントを直した)。
nine_point_full が4倍遅くなった原因: AR が手詰まりの回を使って補助作図を遅らせ、併合のたびに全定理を試し直させていた(試行 3→7)。回復の手と同じ回に行うように直して 220万 → 60万。

#79数値の検算を固定座標にした ― 座標は探索の前に一度だけ置き、各実体の値は元の定義から一度だけ計算する。マージに依存しないので偽のマージが検算を汚さない既定
ユーザー指摘「マージの確認の度に定義までさかのぼってオブジェクトの座標を計算しているのは非効率では? 予め座標を計算してしまうべきでは?」。
以前の仕組み: 数値チェックは、構造が変わるたび(実体の生成・マージ・接続・memo の登録)に自由点の座標を置き直し、同値類を「計算できる最初の定義」で根から評価し直していた。これには効率より重い問題が2つあった。(1) 値がマージに依存する。 同値類に誤った定義や循環する定義が入ると、以後の検算はその値と比べる。(2) 探索中に規則が導いた接続まで、自由点を置くときの前提に数えていた。 偽の接続があると、それを満たすように点を置いて検算が偽を見逃す。導いた接続が積み重なると点を置けなくなり(円の上の点 D・E・F を持つ pascal)、検算が全て判定不能になって、非退化条件の数値判定も素通りになっていた ― #78 の後も pascal だけ、検査なしで偽のマージが出ていた原因。接続の検算は図全体の標本も使っていなかった。
今の仕組み(mmp_core/fixed_coords.rs): 探索の前に前提の接続を固め(freeze_premise_incidences)、自由点をその前提どおりに一度だけ置く。各実体の値はその実体の元の定義と親の実体の値だけで計算して覚え、以後は捨てない。マージの検算は2つの代表元の値の比較、接続の検算は代入1回、値の定まらない作図は「値が定まらない」ことそのもの。前提が数値的に成り立つ問題で使い、使えないときは従来の経路(--no-fixed-coords で比較できる)。
結果: pascal を検査なしで回すと 72秒 → 30秒、偽のマージ 40件・判定不能 40件 → 0件・0件。他の問題は時間も仕事量も変わらなかった(以前の置き直しは、これらの問題では時間の大きな割合ではなかった)。

#78規則に非退化条件を書いた ― マージ前の検査を外しても、座標を置ける問題では偽のマージが1件も起きない既定
ユーザー方針「健全性のチェックは正しくマージできれば本来不要だから、最終的になくても動くようにしたい」。§04 #76 の検査(結論の数値検算と、局所伝播の「数値的に別物なら結合しない」)は偽のマージを却下する安全網で、なぜ偽の結論が出るのかは直していなかった。
道具: --audit-merges を、定理の結論だけでなく全てのマージと接続を実行の直前に数値で確かめ、出どころ(定理・局所伝播・合同閉包・自明な関係)ごとに数えるようにした(mmp_core/census.rs)。--no-merge-checks で安全網を全て外せる。全44問を回して集計するのは bench/census.sh と bench/census_sum.py(最初の偽が、その問題の偽の連鎖の根)。
最初の監査(検査なし): 座標を置ける36問のうち10問で偽のマージが出た。最初の偽の出どころは (1)「垂線 ⇒ 90度」6問 ― 監査の誤りで、他とマージされる前の Ang90(GivenPoint)を (0,0,1) と評価していた。有向角の値(-1)で評価するよう直した。(2) 二次曲線の一意性 3問 ― 2直線に退化した二次曲線どうしが1本の直線を丸ごと共有し、その上の5点を共有して「同じ二次曲線」とされた(centroid)。(3) 二等辺三角形の底角の逆 1問 ― 3頂点が共線(点・中点・もう一方の端点)の「三角形」。検査ありでは、どの問題でも偽のマージは0件だった(安全網は効いていた)。
根本の原因: 規則の「相異なる」は e-graph 上で別の実体かしか見ない。図の上では同じなのに、まだ一致が証明されていないだけの2つの図形を別物として扱うと、退化した配置で偽の結論が出る。
直したもの: (a) 定理: 「相異なる」には2つの役割がある ― 「既に同じなら適用しても意味がない」(枝刈り)と「一致すると定理が偽になる」(非退化条件)。後者を新しいパターン NonDegenerate として書き分け、マッチが完成したときに図の上で数値的に一致しないことを確かめる。全ての「相異なる」を数値で見ると orthocenter が4万→254万、simson が2.9万→298万になり、bench_2019g1 などが落ちた ― 同位角による平行判定(∠(D1,D3)=∠(D2,D3) ⇒ D1=D2)の相異は、まさに一致を結論する相手で、有向角の足し算は方向が一致しても成り立つ。三角形の頂点・3辺、円周上の点、中点の配置などの27組を非退化条件にした(§07 定理 に表示)。(b) 局所伝播: 交点の一意性は2直線が図の上でも別の直線のとき、二次曲線の一意性は共有点からどの4点も共線でない5点を選べるとき、複比の一意性は固定した3点が図の上でも相異なるときだけにした。(c) 値の定まらない作図: 図の上で同じ2直線の交点・同じ2点を通る直線・共線な3点の外接円・3点が共線な5点の二次曲線は、探索の中(補助作図・定理の作図・その場の作図)で作らない。ノイズの作図でも作らない(ノイズは入力なので、ノイズの図そのものが変わった)。
見つかったこと: (1) pappus の以前の「解けた」は誤った推論だった。 証明は、L2 上の3点を含む5点の二次曲線(2直線に退化)どうしを、L2 上の4点を含む共有点で「同じ二次曲線」とマージしていた(4点が共線なら5点で二次曲線は決まらない)。結論はパップスの定理が正しいので真だが、推論は成り立たない。(2) centroid が厳密な証明(626ステップ、複比の透視射影不変性とその逆)で解けるようになった。 (3) ノイズ20の orthocenter_alt の以前の速い解(1,104)は、図の上で値の定まらないノイズの直線の上にあり、「無限遠直線 ≡ Noise6」という偽のマージまでしていた。ノイズ設定の悪化の多くは、ノイズの図が変わったことによる。
非退化条件の費用(同じノイズの図で、条件あり/なし): 両方で解けた問題の仕事量は幾何平均 −0.1〜−1.5%、中央値 ±0。安全網の費用は壁時計で ±3%(12問を1問ずつ)。

試して外したこと ― generic join の「変数の選び方」: 見積もり(estimate_cost)はパターン1本だけを見て候補数を測るので、他のパターンがその変数をきつく縛っていても高く見える。そこで「相手が束縛済みのパターンが生成できる候補数」を集めて上界とし、見積もりをその上界で置き換えた(= 交差後にいちばん小さくなる変数から束縛する)。

分かった順序: b30 の残り(パターンではなく変数を選び、全パターンの候補集合を交差させて cap 自体を要らなくする)を先にやること。変数順序の最適化はその後でないと測れない。

§05 b30(入れ子ループ結合をやめて関係マッチングにする)の第一歩。
