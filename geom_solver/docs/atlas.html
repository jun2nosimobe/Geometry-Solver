01

パイプライン全体

1問につき EGraph::new() → 問題ファイルによる初期条件の投入 → BlackboardEngine によるタスクキュー駆動の定理マッチング、という流れ。探索が完全に手詰まる(Stall)たびにオンデマンド作図の回復フェーズへ落ち、それも尽きればMCTSに委ねる。

02

マッチングの中身(dfs_match)

MatchTask は1つの定理・1つの束縛状態を表し、優先度付きキューで管理される。TheoremDef.patterns を先頭から満たしていくバックトラック探索で、パターンの型(Identical / Connected / DefinedBy / 汎用)ごとに専用の列挙ロジックを持つ。

Identical(v1, v2)

両方未束縛なら型で絞った代表元へ自己束縛(RETE的に定理をまたいで共有キャッシュ済み)。

Connected(child, parent)

e-graphの subobjects を辿る接続判定。両方未束縛のジョインも型だけで決まるため共有キャッシュ済み。

DefinedBy(…, result)

親が揃っていれば memo の O(1) ルックアップ、無ければ一部の型(Angle/Direction/Scalar)はその場で構成 — この副作用性が §3 で扱う設計上の緊張点。

failed_paths

1タスク内の「この束縛状態はもう行き止まり」の記憶。EGraph::type_generation(型ごとの世代カウンタ)が変わらない限り、dfs_cap到達での再キュー間で持ち越せる。

UCB1バンディット

シードなし全探索タスクの優先度を、定理ごとの過去の成功率+探索ボーナスで決める。未試行の定理は常に一度は試す。

4つのゲートウェイ

create_entity / merge_entities / link_logical_incidence / insert_memo。e-graphの生の構造を書き換える経路をここに集約し、type_generation の更新漏れを構造的に防いでいる。

熱量駆動の自己束縛制限(backlog#1)

seeded task経路: 定理単位の絞り込みは5回中5回失敗、結論形式単位の制御が必要

bench_2011balkanmop1(スパイラル相似)未解決の根本原因: 定理の距離配置が合わない

「スパイラル相似の中点対応」定理を実測診断した結果、以前の「前提がStallで確立されない」という推測は不正確だったと判明。本問題ではE=AC∩BD(円に内接する四角形ABCDの対角線の交点)で、実際にログ上でも方冪の定理相当の積の等式(EA・EC=EB・ED)は正しく確立されている――問題は前提の未確立ではなく、定理の構造そのものがこの配置に噛み合わないこと。定理はLineEA,LineEB,LineED,LineECという4本の"Eを通る互いに異なる直線"を要求する(distinct制約)。これは一般の(円で結ばれていない)スパイラル相似中心のような「4方向に開いた頂点」を想定した設計だが、bench_2011balkanmop1のE=AC∩BDでは、Eを通る直線は実際にはAC・BDの2本しかなく(A,E,Cが共線、B,E,Dが共線)、4本のdistinct制約を原理的に満たせない。必要なのは4直線版ではなく、「共点二弦の相似」と同じ2直線配置(LineAB,LineCDがPを通り、LineAD,LineCBは通らない、という非対称な4直線)に相当する、"2直線が交わる点における中点対応"専用の新しい定理――既存定理の使い回しでは届かず、新規のTheoremDef設計(角度対応の一般化+中点という特定の対応点への相似の遺伝)が必要。方針D(§00)が「最終手段として温存」する具体案の1つ。
精密診断済み要・新定理設計

bench_2018silkroadp1/bench_2005ctstp1は新定理不要、既定のMCTS無効+5秒予算が原因

§00方針Cで発見。--mcts --time=30を付けるとbench_2018silkroadp1は3/3回とも一貫して9.1秒で、bench_2005ctstp1も2/3回(18〜33秒)で証明に到達する。A/Bテストで、新設したSecondIntersectionOfLineAndConicを無効化しても同じ結果だったため、既存のMCTSアクションだけで解けていることを確認済み。main.rsのリカバリーフェーズは--mctsが付いていないと需要駆動の補助構成が尽きた時点で探索を完全に打ち切る実装になっており(§01のパイプライン図のJ -->|"いいえ"| L["探索打ち切り"]がまさにこれ)、既定の5秒という時間予算はMCTSがこれらを解くのに要する時間(9〜30秒超)より短い。つまりこの2問は「詰んでいる」のではなく「既定設定でMCTSを試す機会も時間も与えられていない」だけ――#7の4問とは根本的に別カテゴリなので、新定理設計の対象からは除外してよい。

MCTSを既定で有効化するには、時間予算と健全性チェックの両方に手を入れる必要がある
